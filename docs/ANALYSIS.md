# تحليل المتطلبات وخطة التنفيذ

مصدر هذا التحليل: تقرير مشروع التخرج «النظام العسكري الذكي لإدارة الحضور والانضباط» (قيس سيف الناعبي، الكلية العسكرية التقنية). الملف المرفق نصي؛ المخططات والصور الواردة فيه (مخطط جانت، حالات الاستخدام، الفئات، التسلسل، النشاط، النماذج الأولية) لم تكن مضمّنة كصور، فاعتُمد على أوصافها المكتوبة.

## 1. المشروع في سطور

- **المشكلة**: التحضير بالنداء وكشوف ورقية → بطء، أخطاء بشرية، حضور بالنيابة، لا رؤية لحظية، لا مساءلة.
- **الحل**: صورة واحدة للطابور ← اكتشاف كل الوجوه ← مطابقة مع جنود الفصيل ← تسجيل تلقائي، مع تحضير يدوي احتياطي، واعتماد قائد الفصيل، وتقارير، وسجل عمليات.
- **الأهداف**: تسريع التحضير، تقليل الأخطاء، منع النيابة، أتمتة السجلات، تقارير فورية، صلاحيات حسب الدور، حماية البيانات الحساسة.

## 3. الفجوات والتعارضات المكتشفة في التقرير وكيف عولجت

1. **متى يُعدّ الجندي «متأخراً»؟** التقرير يذكر الحالة دون قاعدة. ← **افتراض**: للجلسة وقت بدء مقرر اختياري؛ من يُتعرّف عليه بعد الوقت + مهلة (10 دقائق افتراضياً) يُسجَّل متأخراً، ويبقى التعديل اليدوي ممكناً.
2. **تقارير السنير**: متطلبات المستخدم تقول «المستخدمون المصرّح لهم»، والجدول 3 لا يعطي السنير تقارير. ← اتُّبع الجدول 3 (الأدق)؛ السنير يرى جلسات فصيله فقط.
3. **«المزامنة عند عودة الخدمة»** وردت في إدارة المخاطر بينما العمل دون اتصال مؤجّل لمراحل لاحقة. ← نُفّذ جزء صغير آمن: طابور محلي للتحضير **اليدوي فقط** يُرسل تلقائياً عند عودة الشبكة ويعيد الخادم التحقق منه. التعرف بالوجه يبقى متصلاً.
4. **الأداء 5 ثوانٍ لـ 50 وجهاً** غير مضمون بنموذج `buffalo_l` على معالج ضعيف. ← النموذج قابل للتبديل بمتغير، والقياسات الفعلية موثقة أعلاه.
5. **ترخيص InsightFace** (بحثي فقط) — قيد قانوني يجب حله قبل الإنتاج (موثّق في README).
6. **من يعدّل بعد الاعتماد؟** غير محدد. ← **افتراض**: الجلسة المعتمدة مقفلة؛ أي تصحيح لاحق يحتاج قراراً تنظيمياً (لم تُضف واجهة «إلغاء اعتماد» عمداً).
7. **تغيير النموذج** يجعل البصمات القديمة غير قابلة للمقارنة. ← كل قالب يحمل اسم النموذج، والمطابقة تتجاهل القوالب من نموذج مختلف.
8. **الواجهة**: التقرير يحدد Angular PWA للهاتف. (ملاحظة: إذا كانت هناك نسخة Flutter قيد التطوير، فهي تستطيع استخدام واجهات REST نفسها دون تعديل.)

## 4. التحسينات المقترحة والمضافة

كل بند أدناه **ليس في التقرير الأصلي** وأُضيف لأنه يخدم أهدافه مباشرة:

| التحسين | السبب | الفائدة |
|---|---|---|
| تعيين شامل واحد-لواحد للوجوه بدلاً من «أعلى تشابه لكل وجه» | منطق «لكل وجه أفضل جندي» قد يعطي جندياً واحداً لوجهين | لا ازدواج ولا سرقة هوية بين وجهين متشابهين |
| رفض تسجيل وجه يطابق جندياً آخر (`DUPLICATE_IDENTITY`) | يمنع خطأ التسجيل أو التحايل بتسجيل شخص باسم غيره | سلامة الهوية من المصدر |
| فحص اتساق صور الجندي نفسه (`SELF_MISMATCH`) | منع خلط صور شخصين في ملف واحد | قوالب أنظف = دقة أعلى |
| رفض الوجه الصغير والضبابي عند التسجيل | جودة القالب تحدد دقة التعرف | تقليل الرفض الخاطئ |
| تسجيل الموافقة البيومترية (من/متى) وحذف فوري عند سحبها أو إنهاء الخدمة | متطلب قانوني في التقرير دون آلية | التزام فعلي بسياسة الاحتفاظ |
| ربط القالب المشفّر برقم الجندي (AAD) | نسخ قالب إلى صف جندي آخر يفشل في فك التشفير | منع التلاعب في قاعدة البيانات |

| رمز تجديد دوّار في كوكي HttpOnly + كشف إعادة الاستعمال | تخزين JWT في localStorage معرض لـ XSS | جلسات آمنة على الهواتف المشتركة |

| رفض الإقلاع عند غياب الأسرار | منع تشغيل الإنتاج بأسرار فارغة | — |

| مهلة التأخير ووقت البدء المقرر | لتحديد «متأخر» آلياً | — |
| صفحة إعدادات للعتبة والمهلة ومدة الاحتفاظ | التقرير يطلب «ضبط العتبة أثناء الاختبار الميداني» | ضبط دون إعادة نشر، ومسجّل في سجل العمليات |

## 5. خطة التنفيذ (كما نُفّذت)

1. المخطط وقيود قاعدة البيانات (Flyway) — واختباره على PostgreSQL 16.
2. خدمة الوجوه + اختبارات بنموذج حقيقي.
3. الخادم: الأمان ← الكيانات ← الصلاحيات ← الجنود والتسجيل ← الجلسات والمطابقة ← الاعتماد ← المتابعة ← التقارير والتصدير ← سجل العمليات والإعدادات.
4. الواجهة: الأساس (مصادقة، ترجمة، حراس) ← الهيكل المتجاوب ← الصفحات ← PWA.
5. الدمج: Docker Compose وNginx/TLS وCI.
6. الاختبار والتوثيق.

## 6. المخاطر التقنية المتبقية

| الخطر | المعالجة |
|---|---|
| دقة التعرف في الإضاءة الصعبة والخوذ | تعدد صور التسجيل، عتبة قابلة للضبط، مراجعة بشرية واعتماد، يدوي متاح دائماً |
| الانتحال بصورة مطبوعة/شاشة | التقاط الصورة من السنير لا الجندي؛ كشف الحياة (Liveness) مؤجل كما في التقرير |
| الأداء على CPU ضعيف | `buffalo_s`، `FACE_DET_SIZE`، أكثر من نسخة من الخدمة |
| الفروق السكانية في الدقة (NIST FRVT) | تقييم ميداني على صور المستخدمين قبل التعميم |
| الترخيص والموافقات | قبل الإنتاج، موثّق |

## 7. ما لم يُنفّذ (مؤجّل كما في التقرير أو يحتاج قراراً)

- التعرف من بث الفيديو وكاميرات IP الثابتة، كشف الحياة، الربط مع البصمة وRFID والبوابات والرواتب والإجازات، عدّ الأشخاص بـ YOLO.
- العمل الكامل دون اتصال (التعرف بالوجه يحتاج الخادم).
- البحث المتجهي `pgvector` (المطابقة الحالية داخل الفصيل فقط وتكفي لعشرات الجنود؛ يلزم عند آلاف الجنود في نطاق واحد).
- إلغاء اعتماد جلسة، وتصدير سجل العمليات.
- إشعارات فورية (Push) للقادة.
